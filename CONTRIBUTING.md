# Contributing

1. Create a governed-change issue that states the need, beneficiaries, measurable acceptance conditions, and affected operating conditions.
2. Initialize the copied template before changing `src/` or `tests/`.
3. Use a CLSES work request or bounded autonomy mandate for application and test changes. Never manufacture an approval or evidence record.
4. Keep specification acceptance, engineering authorization, artifact acceptance, and deployment authorization as separate exact decisions by the declared human roles.
5. Open a pull request using the supplied template. CI must pass, and branch protection must require review before merge.

Changes to the embedded kernel, workflows, schemas, profiles, adapters, or governance documents require a new template release assessment and template-manifest digest.
